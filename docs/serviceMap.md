## 🔒 Runtime boundaries

`accountsService` owns password credentials; `authService` owns authorization principals and tokens. `virtualMoney` would own one internal ledger and table escrow; `cryptoService` would only adapt agreed external observations. `pokerService` coordinates one authoritative engine instance per table and serializes commands. A player receives only the allowed public/player view, never the trusted server view. No service reads or writes another service's database.

The engine's newline-delimited JSON/TCP server and curses client demonstrate flows without production TLS or authentication. They are references, not a selected production transport. The SDK's HTTP control plane does not imply WebSocket or gameplay transport support. No lobby, gateway, separate funds ledger, blockchain indexer, custody or wallet repository is implied by this map.

## 📦 Verification and open decisions

The local service foundations pass their lock, lint, type, technical HTTP/CLI and wheel checks. `authService` and `accountsService` preserve five and three historical Alembic revisions respectively; their positive PostgreSQL/readiness jobs are configured but have not run on these local commits. Standalone Copier updates passed for `accountsService` and `pokerClient` with canonical source URLs mapped to local committed checkouts for the offline probe. Hosted CI, private SDK BuildKit stages, Docker images, PR heads and current GitHub App/secret scope were not read back for these commits because remote authentication is unavailable. Earlier PR runs are not evidence for these new SHAs. No subject suite, business migration or production operation was exercised. Infrastructure readiness is not gameplay, token issuance, ledger or payment readiness.

Product decisions still needed: table transport and durable ownership; account/token operations; internal ledger contract; whether deposits or withdrawals exist; external networks/assets/provider, custody/signing, amount units, finality/reversal, retries, reconciliation and permissions. The verified `virtualMoney` main branch has only `alembic/versions/.gitkeep`; the README's revision discussion does not establish an applied revision graph. No business endpoint or live database migration is authorized by this map.
